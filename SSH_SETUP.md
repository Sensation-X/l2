# SSHSetup.md — подключаемся к серверу по SSH (для непрофи)

**SSH** — это терминал твоего сервера у тебя на компьютере. Команды, которые ты вводишь в PowerShell после `ssh root@…`, выполняются НА сервере, а не на ПК.

Твой сервер: VPS Beget, Ubuntu, IP `31.207.75.248`, пользователь `root`.
Пароль root тебе выдавал Beget (письмо «VPS создан» или раздел панели с реквизитами).

Главное правило безопасности на этом сервере: **выполняем только команды из наших инструкций и только с явными путями** (`/var/www/hurmych`, `/root/hurmych`). У тебя там уже живёт другой проект — мы его не трогаем никак: ни файлов, ни общих конфигов без предварительной разведки.

## Шаг 0. Проверь, что на Windows есть SSH-клиент

В PowerShell:

```powershell
ssh -V
```

Ожидаемо: `OpenSSH_for_Windows_8.x` или похожее. Если «не является командой» — ставь: «Параметры → Приложения → Дополнительные компоненты → Добавить компонент → Открытый клиент OpenSSH».

## Шаг 1. Поставь вход по ключу (без пароля) одной командой

Ключ = файл-пароль, который живёт только на твоём ПК. Дальше сервер не будет спрашивать пароль, и это безопаснее пароля.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/ssh_setup.ps1
```

Обрати внимание: слэш в пути **прямой** (`scripts/ssh_setup.ps1`), не обратный — так команда копируется без обрезаний.

Скрипт:
1. создаст ключ `C:\Users\ТВОЙ_ПОЛЬЗОВАТЕЛЬ\.ssh\id_ed25519`, если его нет;
2. попросит ввести пароль root **два раза** (один раз на копирование ключа, второй на проверку);
3. проверит вход без пароля и напишет `SSH_OK`.

Что ты увидишь по шагам и как реагировать:

| Что появилось на экране | Что делать |
|---|---|
| `The authenticity of host ... can't be established ... yes/no/[fingerprint]?` | это первый вход, сервер показывает отпечаток ключа. Напечатай `yes` и Enter |
| `root@31.207.75.248's password:` | введи пароль root и Enter. **Символы не отображаются вообще** — ни звёздочек, ни курсора. Это нормально |
| `KEY_INSTALLED` | ключ скопирован |
| `SSH_OK_…` | вход без пароля работает |

## Шаг 2. Проверка руками

```powershell
ssh root@31.207.75.248 "hostname && whoami && pwd"
```

Ожидаемо: имя сервера, `root`, `/root`. Если вошёл БЕЗ запроса пароля — ключ работает.

## Шаг 3. Разведка сервера (читает, ничего не меняет)

У тебя на сервере уже есть проект. Прежде чем ставить сайт, я должен увидеть, какой веб-сервер там работает и что занято. Команда отправляет скрипт разведки на сервер и печатает отчёт у тебя:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/recon.ps1
```

(В PowerShell нельзя перенаправлять файл в команду через `<`, поэтому разведка обёрнута в свой скрипт: он сам скопирует `recon.sh` на сервер и выполнит его.)

Изоляцию делаем папками и отдельным сайт-блоком:

| Путь | Назначение |
|---|---|
| `/var/www/hurmych/` | только файлы сайта «Хурмыч» |
| `/root/hurmych/` | служебное: дистрибутив сайта, скрипты деплоя |

## Если что-то пошло не так

| Симптом | Лечение |
|---|---|
| `Permission denied (publickey,password)` | неверный пароль root; возьми актуальный в панели Beget (раздел VPS → реквизиты) или сбрось пароль в панели |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | сервер переустанавливали; удали старую запись: `ssh-keygen -R 31.207.75.248` и повтори |
| Таймаут подключения | проверь, что сервер «Запущен» в панели; попробуй вход через веб-терминал VNC в панели Beget |
| Забыл пароль и не заходит | в панели Beget у VPS есть кнопка сброса пароля root |
| Всё работает, но хочу обратно пароль | не надо: ключ безопаснее; пароль можно отключить позже осознанно |
